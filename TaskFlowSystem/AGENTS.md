# Правила WPF-клиента

Это локальное правило дополняет корневой `AGENTS.md` и действует для
`TaskFlowSystem/`.

## Технологии и стиль

- Целевая платформа — .NET Framework 4.7.2, WPF и существующий старый-format
  `.csproj`. Проверяйте совместимость синтаксиса, библиотек и API с этой
  платформой.
- XAML отвечает за структуру, стили и binding; code-behind — за тонкие события
  окна. Бизнес-правила, файловый доступ и HTTP-клиенты выносите в отдельные
  классы/сервисы, а не добавляйте в `MainWindow.xaml.cs`.
- Соблюдайте текущую структуру namespace `TaskFlowSystem` и code-behind
  `x:Class`. Новые XAML-файлы не забудьте включить в `.csproj`.
- Не редактируйте сгенерированные файлы в `bin/`, `obj/` и `Properties/*Designer.cs`.

## Состояние приложения

- `ProfileStore` — текущая локальная граница хранения профилей. Сохраняйте
  изоляцию по стабильному `LocalProfile.Id`; имя, описание, цвет и аватар —
  отображаемые поля, а не ключи.
- В первом релизе не добавляйте обязательный вход в интернет, регистрацию,
  пароль, токен или сетевой вызов. Локальный профиль — это выбор контекста, а
  не подтверждение личности.
- Локальные задачи должны фильтроваться по активному профилю и явно выбранной
  области видимости. Не считайте все данные на компьютере автоматически
  доступными любому профилю.
- Ошибка чтения локального состояния не должна silently превращаться в потерю
  данных. Сохраняйте безопасный fallback, но сообщайте пользователю, если
  действие не удалось записать.
- Не создавайте отдельное несогласованное состояние профиля в каждом окне.
  Активный профиль должен передаваться явно или находиться в одном сервисе
  состояния.
- Долгие операции файлового доступа не должны блокировать UI-поток. Используйте
  совместимый с .NET Framework async-подход и корректно отменяйте операции при
  закрытии окна. Сетевые операции не нужны локальному MVP.

## XAML и взаимодействие

- Переиспользуйте ресурсы темы и существующие стили. Новые цвета сначала
  добавляйте в общий ресурс, а не в десятки локальных атрибутов.
- Для каждой формы предусмотрите валидацию, фокус на первой ошибке, Enter/Escape
  только когда это не конфликтует с вводом, и понятное состояние сохранения.
- Не используйте placeholder как реальное значение модели. Перед поиском или
  сохранением отделяйте текст-подсказку от введённого значения.
- У кнопок и иконок задавайте `AutomationProperties.Name`; не полагайтесь на
  один символ вроде `✕` или `›` как на доступное описание.
- Не выполняйте тяжёлое построение большого списка синхронно в `Loaded`.
  Для списков задач подготовьте paging/виртуализацию до масштабирования.

## Проверка клиента

- Собирайте WPF-проект через Visual Studio/MSBuild под .NET Framework 4.7.2.
- Минимально вручную проверяйте запуск без профилей, создание профиля с
  некорректным именем, выбор/переключение, удаление, повторный запуск и
  повреждённый `profiles.json`.
- Для задач проверяйте обязательные поля: название, статус, срок выполнения и
  описание; отдельно проверяйте сохранение комментария, вложения, тега и записи
  истории.
- При изменении XAML проверяйте размеры окна, DPI/масштабирование, клавиатурную
  навигацию и состояния hover/pressed/disabled.
